# Requirements: AI-Native Messaging Protocol — iOS Reference Client

**Defined:** 2026-03-29
**Core Value:** Enable mixed human-agent threads where any participant (human or agent) can seamlessly join, communicate, and coordinate — with the same quality of experience regardless of who's a person and who's an AI.

## v1 Requirements

Requirements for the native iOS reference client. Each maps to roadmap phases.

### Networking & Identity

- [x] **NET-01**: App connects to AINM server via WebSocket with JSON-RPC 2.0 framing
- [x] **NET-02**: App completes `ainm.initialize` handshake with capability negotiation
- [x] **NET-03**: User can set server URL and display name during onboarding (simple identity flow)
- [x] **NET-04**: App generates Ed25519 keypair and stores private key in iOS Keychain
- [x] **NET-05**: App signs all outgoing messages with Ed25519 via Apple CryptoKit
- [x] **NET-06**: App implements RFC 8785 JCS canonicalization matching Rust server output

### Core Messaging

- [x] **MSG-01**: User can view conversation list with thread title, last message preview, and timestamps
- [x] **MSG-02**: User can view message thread with chronological messages and participant avatars
- [x] **MSG-03**: User can send text messages with Markdown rendering
- [x] **MSG-04**: App renders multi-block messages (text + code + image in sequence)
- [x] **MSG-05**: App renders CodeBlocks with syntax highlighting, language label, and copy button
- [x] **MSG-06**: App renders ImageBlocks with tap-to-fullscreen and size pre-layout
- [x] **MSG-07**: App renders FileBlocks with filename, size, and download capability
- [x] **MSG-08**: User can create threads with mixed human and agent participants
- [x] **MSG-09**: App displays agent identity distinctly (type badge, profile shows Agent Card data)

### Streaming & Real-Time

- [x] **STR-01**: App renders streaming responses token-by-token with cursor animation
- [x] **STR-02**: App shows typing/processing indicators for humans and agents
- [x] **STR-03**: User can cancel an active streaming response
- [x] **STR-04**: App handles parallel block streaming (multiple blocks receiving deltas simultaneously)

### Interactive Blocks

- [x] **INT-01**: App renders ButtonBlocks with semantic styles and sends ActionBlock on tap
- [x] **INT-02**: App renders FormBlocks with all field types and client-side validation
- [x] **INT-03**: App renders TableBlocks with horizontal scroll and row actions
- [x] **INT-04**: App renders ApprovalBlocks with state machine (pending/approved/rejected/changes_requested)
- [x] **INT-05**: App renders fallback text for unrecognized block types

### AI-Native Features

- [x] **AI-01**: App shows tool call visibility (collapsible indicators with lifecycle grouping)
- [x] **AI-02**: App supports @-mentions with highlighting and composer autocomplete
- [x] **AI-03**: User can browse agent discovery (Agent Cards with skills, tools, capabilities)
- [x] **AI-04**: App displays memory context (active context frames, conversation history)
- [x] **AI-05**: User can view, search, and delete archival memory facts per agent

### Persistence & Platform

- [x] **PLT-01**: App caches messages, threads, and participants locally via GRDB.swift
- [x] **PLT-02**: App provides offline access to cached messages
- [x] **PLT-03**: App supports light and dark mode via SwiftUI semantic colors
- [x] **PLT-04**: User can branch sub-threads from any message (one level per spec)
- [x] **PLT-05**: App supports deep linking to specific threads and messages

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Push & Background

- **PUSH-01**: App receives push notifications for new messages via APNs
- **PUSH-02**: Notification tap opens correct thread
- **PUSH-03**: Server-side APNs device token registration protocol extension

### Platform Expansion

- **PLAT-01**: iPad layout with split view navigation
- **PLAT-02**: Mac Catalyst support
- **PLAT-03**: Accessibility audit (VoiceOver, Dynamic Type, reduced motion)

### Advanced Features

- **ADV-01**: Extension block plugin architecture for custom renderers
- **ADV-02**: Verified message badges (cryptographic verification indicators)
- **ADV-03**: Connection status indicator (connecting/connected/reconnecting/offline)
- **ADV-04**: Tool call timeline (aggregate view of all tool calls in thread)
- **ADV-05**: Haptic feedback on interactive block actions

### Federation UI

- **FED-01**: Federated identity display (show participant's server domain)
- **FED-02**: Cross-server conversation support in UI

## Out of Scope

| Feature | Reason |
|---------|--------|
| Voice/video messaging | Text and rich content only for v1 — massive WebRTC complexity |
| Agent marketplace/store | Discovery yes, marketplace no — premature commerce layer |
| End-to-end encryption | Server-visible messages needed for agent processing, search, memory |
| Custom themes/skins | Light/dark mode only — focus on one polished visual identity |
| Slash commands for bots | Old paradigm — AINM agents are @-mentioned participants, not command responders |
| Read receipts | Not in AINM v1 protocol — presence indicators serve the purpose |
| Message reactions (emoji) | Not in AINM v1 protocol — would create protocol divergence |
| Offline message composition queue | Over-engineering for v1 — disable send when offline |
| ChartBlock rendering | Deliberately excluded from protocol spec |
| Self-hosting tools | App connects to servers, doesn't bundle one |
