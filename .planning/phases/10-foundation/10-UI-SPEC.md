# Phase 10 — UI Design Contract

> Visual and interaction contract for the Foundation phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase 10 scope:** Onboarding screen only. All other UI is deferred to Phase 11+. The goal is infrastructure validation, not UI polish.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native SwiftUI) |
| Preset | not applicable |
| Component library | SwiftUI built-in components |
| Icon library | SF Symbols (system) |
| Font | San Francisco (system default via `.body`, `.headline`, etc.) |

**Rationale:** Phase 10 is a greenfield iOS project using pure SwiftUI (per CLAUDE.md). No web design system applies. SwiftUI semantic styles (`.font(.body)`, `Color.primary`) are used to ensure automatic light/dark mode support from day one, ahead of PLT-03 in Phase 11.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | SwiftUI Usage |
|-------|-------|---------------|
| xs | 4pt | Icon gaps, inline padding |
| sm | 8pt | Compact element spacing, TextField internal padding |
| md | 16pt | Default element spacing, form field vertical gaps |
| lg | 24pt | Section padding within onboarding |
| xl | 32pt | Top/bottom safe area insets, layout margins |
| 2xl | 48pt | Major section breaks |
| 3xl | 64pt | Not used in Phase 10 |

Exceptions: Touch targets minimum 44pt per Apple HIG (applies to Connect button).

---

## Typography

Phase 10 uses SwiftUI Dynamic Type text styles exclusively. No custom font sizes. This ensures automatic accessibility scaling.

| Role | SwiftUI Style | Approx Size | Weight | Line Height |
|------|---------------|-------------|--------|-------------|
| Body | `.body` | 17pt | regular (400) | 1.47 (22pt) |
| Label | `.subheadline` | 15pt | regular (400) | 1.33 (20pt) |
| Heading | `.title2` | 22pt | bold (700) | 1.27 (28pt) |
| Caption | `.caption` | 12pt | regular (400) | 1.33 (16pt) |

**Weights used:** 2 only -- regular (400) for body/labels, bold (700) for headings. No semibold, no light.

---

## Color

Phase 10 uses SwiftUI semantic colors exclusively. No custom hex values. This guarantees correct light/dark mode behavior from day one.

| Role | SwiftUI Token | Usage |
|------|---------------|-------|
| Dominant (60%) | `Color(.systemBackground)` | Screen background |
| Secondary (30%) | `Color(.secondarySystemBackground)` | Form container, grouped content area |
| Accent (10%) | `Color.accentColor` (system blue by default) | Connect button, active text field border |
| Destructive | `Color.red` | Error text, failed connection state |

Accent reserved for: Connect button fill, active/focused TextField tint, loading spinner. Nothing else in Phase 10.

**Custom accent color:** Not set in Phase 10. Use system default (blue). A branded accent color will be defined in Phase 11 when the full messaging UI is designed.

## Component Inventory

Phase 10 has exactly one user-facing screen and one debug screen.

### Screen 1: Onboarding (NET-03, NET-04)

```
+------------------------------------------+
|                                          |
|              [App Icon/Logo]             |
|                                          |
|         AI-Native Messenger              |  <- .title2, bold, centered
|                                          |
|  +------------------------------------+  |
|  | Server URL                         |  |  <- TextField, .subheadline label
|  | wss://                             |  |
|  +------------------------------------+  |
|                                          |  <- 16pt gap
|  +------------------------------------+  |
|  | Display Name                       |  |  <- TextField, .subheadline label
|  |                                    |  |
|  +------------------------------------+  |
|                                          |  <- 24pt gap
|  +------------------------------------+  |
|  |           Connect                  |  |  <- .borderedProminent button, 44pt min
|  +------------------------------------+  |
|                                          |
|  [ Inline error message if any ]         |  <- .caption, Color.red
|                                          |
+------------------------------------------+
```

**States:**

| State | Visual Behavior |
|-------|----------------|
| Idle | Connect button enabled when both fields non-empty |
| Connecting | Connect button shows ProgressView (spinner) + "Connecting..." label. Both fields disabled. |
| Connected | Navigate away to a placeholder "Connected" screen (Phase 10 success view) |
| Error | Inline error text below Connect button in `Color.red`, `.caption` style. Fields remain editable. Button returns to "Connect". |

**Interaction details:**
- Server URL field: `UIKeyboardType.URL`, autocapitalization off, autocorrect off
- Display Name field: standard keyboard, autocapitalization `.words`
- Connect button: `.buttonStyle(.borderedProminent)`, minimum height 44pt
- Tapping Connect: generates Ed25519 keypair silently (NET-04), then initiates WebSocket connection (NET-01) and handshake (NET-02)
- Pre-fill server URL: Yes, pre-fill with `wss://localhost:8080` for developer convenience (Claude's discretion item from CONTEXT.md -- chosen because Phase 10 targets developers testing against local Rust server)

### Screen 2: Connection Success (debug/validation)

```
+------------------------------------------+
|                                          |
|         Connected                        |  <- .title2, bold
|                                          |
|  Server: wss://localhost:8080            |  <- .body
|  Identity: alice@localhost               |  <- .body
|  Capabilities: [list from server]        |  <- .body
|                                          |
|  +------------------------------------+  |
|  |        Send Test Message           |  |  <- .borderedProminent
|  +------------------------------------+  |
|                                          |
|  Signature: verified / failed            |  <- .caption, green/red
|  JCS Match: verified / failed            |  <- .caption, green/red
|                                          |
|  +------------------------------------+  |
|  |          Disconnect                |  |  <- .bordered, Color.red tint
|  +------------------------------------+  |
|                                          |
+------------------------------------------+
```

**Purpose:** This screen validates success criteria 1-5. Not a production UI -- it is a developer-facing validation harness that proves:
- WebSocket connection + handshake (SC-1)
- Outgoing Ed25519 signing with JCS (SC-2)
- Incoming signature verification (SC-3)
- Keypair persistence survives restart (SC-4, shown by re-connecting after kill)
- GRDB persistence (SC-5, shown by data surviving termination)

## Accessibility Baseline

Phase 10 establishes accessibility defaults that carry through all subsequent phases.

| Concern | Approach |
|---------|----------|
| Dynamic Type | Use SwiftUI text styles (`.body`, `.title2`, etc.) -- automatic scaling |
| VoiceOver | All interactive elements get `.accessibilityLabel`. Connect button: "Connect to server". |
| Color contrast | SwiftUI semantic colors meet WCAG 2.1 AA by default in both light and dark mode |
| Touch targets | Minimum 44pt height on all tappable elements (Apple HIG) |
| Reduced motion | No custom animations in Phase 10 -- nothing to adapt |
