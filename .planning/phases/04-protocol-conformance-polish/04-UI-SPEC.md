# Phase 4 -- UI Design Contract

> Visual and interaction contract for the terminal CLI demo. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase scope note:** Phase 4 has NO web frontend work. All "UI" is ANSI terminal output rendered by the Rust `colored` crate in `demo/src/render.rs`. The Docusaurus website receives only mirrored schema files -- no page or component changes. This contract specifies the terminal rendering conventions for new scenarios (`/memory`, `/bridge`) and fixes to existing rendering (`ApprovalBlock` field names).

## Spacing Scale

Terminal output uses character-based spacing, not pixel-based. All indentation uses space characters.

| Token | Value | Usage |
|-------|-------|-------|
| indent-0 | 0 spaces | Section separators (`println!()` blank line) |
| indent-1 | 2 spaces | Primary content blocks (text, code, buttons, messages) |
| indent-2 | 4 spaces | Nested content (form fields, tool details, option lists) |
| indent-3 | 6 spaces | Deep nesting (sub-items within nested content) |
| separator | blank line (`println!()`) | Between message envelopes, between scenario sections |

Exceptions: none. All existing rendering in `render.rs` uses 2-space base indentation. New `/memory` and `/bridge` renderers MUST match this pattern.

**Source:** Direct reading of `demo/src/render.rs` -- every `println!()` call uses `"  {}"` (2-space indent) for primary content and `"    {}"` (4-space indent) for nested items.

## Typography

Terminal "typography" is ANSI formatting via the `colored` crate. There are no font size or weight choices -- the user's terminal font applies universally. The contract specifies color and style modifiers.

| Role | ANSI Style | `colored` Method | Usage |
|------|-----------|------------------|-------|
| Sender identity | Cyan | `.cyan()` | `[user@demo.ainm.local]`, `[helper@demo.ainm.local]` |
| Verified badge | Green | `.green()` | `[VERIFIED]` after messages and streams |
| Failed badge | Red | `.red()` | `[FAILED]` for signature verification failure |
| Timestamp | Dimmed | `.dimmed()` | ISO 8601 timestamps after sender header |
| Code content | Cyan | `.cyan()` | Lines within code blocks |
| Code fence | Dimmed | `.dimmed()` | ` ``` ` markers and language identifier |
| Section header | Yellow + Bold | `.yellow().bold()` | `=== Title ===` for forms, scenario headers |
| Primary action | Blue + Bold | `.blue().bold()` | `[ Label ]` primary-style buttons |
| Success action | Green + Bold | `.green().bold()` | `[ Submit ]` form buttons, approve options |
| Danger action | Red + Bold | `.red().bold()` | `[ Reject ]` danger-style buttons |
| Secondary action | White | `.white()` | `[ Label ]` secondary-style buttons |
| Tool started | Yellow | `.yellow()` | `>> Tool: name - description` |
| Tool progress | Dimmed | `.dimmed()` | `   progress_text [N%]` |

## Color

Terminal color contract uses named ANSI colors (not hex values). The terminal emulator determines actual RGB values.

| Role | ANSI Color | Usage |
|------|-----------|-------|
| Dominant (structural) | Default terminal foreground | All body text, explanations, descriptions |
| Identity (30%) | Cyan | Sender addresses, Agent Card borders, code content |
| Accent -- success (10%) | Green | Verified badges, successful tool completions, approve buttons, submit buttons |
| Accent -- warning (10%) | Yellow | Tool activity indicators, section headers, approval prompts, tool/skill names |
| Destructive | Red | Failed badges, danger buttons, failed tool completions, required field markers |
| Muted | Dimmed | Timestamps, code fences, field types, progress text, fallback content, approval status |
| Emphasis | Bold | Agent Card names, section headers (combined with yellow), action labels (combined with color) |

Accent reserved for:
- **Green:** Signature verification success (`[VERIFIED]`), tool completion success, form submit buttons, approve-style options
- **Yellow:** Active tool events (`>> Tool:`), section headers (`=== ===`), approval prompts (`! APPROVAL !`), tool/skill names in Agent Card
- **Red:** Signature verification failure (`[FAILED]`), tool completion failure, danger-style options, required field markers

**Source:** Existing `render.rs` color assignments. New `/memory` and `/bridge` renderers MUST use the same color semantics -- no new colors introduced.

## New Renderer Specifications

### `render_memory_event(event_type, params)` -- NEW

Renders memory operation results in the terminal. Must follow existing patterns in `render.rs`.

```
  === Memory Operations Demo ===              <- yellow + bold (matches form headers)
  Stored archival fact: user_preference.demo   <- green (matches success pattern)

  Archival memory query results:               <- default foreground
    - user_preference.demo: "Prefers..."       <- yellow key, default value (matches tool name pattern)

  === Context Frame Received ===               <- yellow + bold
    [active_context] (2048 bytes)              <- cyan section name, dimmed byte count
    [conversation_memory] (4096 bytes)         <- cyan section name, dimmed byte count
    [archival_facts] (512 bytes)               <- cyan section name, dimmed byte count
    [agent_instructions] (256 bytes)           <- cyan section name, dimmed byte count
```

### `render_bridge_event(bridge_type, params)` -- NEW

Renders bridge simulation output. Must follow existing patterns in `render.rs`.

```
  === Bridge Compatibility Demo ===            <- yellow + bold

  --- MCP Bridge ---                           <- cyan + bold (matches Agent Card border style)
  Simulating MCP tool bridge: external tool... <- default foreground
  Bridge Agent: MCP Code Tools Bridge          <- bold name (matches Agent Card name style)
  >> Tool: file_read - Read file contents      <- yellow (reuses render_tool_event)
     Reading /src/main.rs... [50%]             <- dimmed (reuses render_tool_event)
  >> Tool complete: 42 lines read (150ms)      <- green (reuses render_tool_event)

  --- A2A Bridge ---                           <- cyan + bold
  Simulating A2A task delegation: external...  <- default foreground
  A2A task submitted -> sub-thread created     <- yellow (event indicator)
  A2A task working -> agent processing         <- dimmed (progress indicator)
  A2A task completed -> result delivered        <- green (success indicator)
```

### Agent Card Renderer Updates (FINDING-07, -08)

The existing `render_agent_card` in `render.rs` already handles `ainm.streaming`, `ainm.contentTypes`, and `ainm.tools`. It needs additions for the new required sub-objects:

| New Field Path | Render Format |
|---------------|---------------|
| `ainm.protocolVersion` | `  Protocol:   {version}` (default foreground, after Version line) |
| `ainm.streaming.parallelBlocks` | `  Parallel:    {true/false}` (default foreground, in streaming section if expanded) |
| `ainm.streaming.preferredChunkSize` | `  Chunk size:  {value}` (default foreground) |
| `ainm.threading.subThreads` | `  Threads:     sub-threads {enabled/disabled}` (default foreground) |
| `ainm.threading.maxConcurrentThreads` | `  Concurrency: {N} threads` (default foreground) |
| `ainm.memory.archivalSupported` | `  Memory:      archival {supported/not supported}` (default foreground) |
| `ainm.memory.contextFramePreferred` | `  Context:     frame delivery {preferred/not preferred}` (default foreground) |

These new fields render between the existing `Content:` line and `Tools:` section in the Agent Card display.
