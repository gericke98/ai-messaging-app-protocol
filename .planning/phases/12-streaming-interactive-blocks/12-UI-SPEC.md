## Design System

| Property | Value |

## Focal Point

Primary visual focal point during streaming: the accumulating text in the StreamingMessageView at the bottom of the thread, anchored by the blinking cursor. All auto-scroll behavior and layout decisions prioritize keeping this focal point visible when the user has not manually scrolled away.

## Component Inventory

### Component 1: StreamingMessageView (STR-01, STR-04)

**Layout:** Renders inside the message thread at the bottom, appearing as an agent message in progress. Uses the same `AgentMessageView` container style (left-aligned, full-width, secondarySystemGroupedBackground, 12pt corner radius).

**Streaming text rendering:**
- Text accumulates character-by-character inside a `Text` view
- Blinking cursor: 2pt wide, accent-colored vertical bar at the end of the last text line
- Cursor animation: `withAnimation(.easeInOut(duration: 0.5).repeatForever(autoreverses: true))` on opacity (0.0 to 1.0)
- Gate cursor behind `accessibilityReduceMotion` -- show static cursor (opacity 1.0) when reduce motion is enabled
- Multiple blocks render as vertical stack with 8pt spacing between blocks

**Parallel block streaming (STR-04):**
- Each block in the declared layout renders independently
- Code blocks show language label immediately from `stream.start` block layout
- Text and code blocks accumulate independently from their respective deltas

**Ephemeral-to-permanent transition:**
- On `stream.end`, do NOT remove the streaming view immediately
- Transition to "finalizing" state: cursor disappears, content remains visible
- When collapsed `ainm.message.deliver` arrives and is persisted to GRDB, the GRDB observation replaces the streaming placeholder seamlessly (matched by pre-assigned `message_id`)
- If collapsed message does not arrive within 5 seconds, show "Not verified" badge (SF Symbol `exclamationmark.triangle.fill`, caption, secondary color) below the message. VoiceOver: `.accessibilityLabel("Message not verified")`, `.accessibilityHint("The signed message was not received from the server within the expected time.")`

### Component 2: CursorView (STR-01)

**Layout:** Inline element appended to the end of the last line of streaming text.

**Appearance:**
- Width: 2pt
- Height: matches current font's cap height (approximately 12pt for body text, 10pt for code)
- Color: `Color.accentColor`
- Corner radius: 1pt

**Animation:**
- Opacity oscillates between 0.0 and 1.0
- Duration: 0.5 seconds per cycle
- Easing: `.easeInOut`
- Respects `accessibilityReduceMotion`: static at opacity 1.0 when enabled

### Component 3: StopGeneratingButton (STR-03)

**Layout:** Centered horizontally below the streaming message, above the composer. Appears when any stream is active in the current thread. Disappears when all streams end.

**Appearance:**
- Capsule shape (`.capsule`)
- Background: `Color(.secondarySystemBackground)`
- Border: 1pt `Color(.separator)`
- Padding: 12pt horizontal, 8pt vertical
- Leading icon: SF Symbol `stop.fill` at 12pt, `Color(.label)`
- Label: "Stop Generating" in `.subheadline` weight bold
- Height: 36pt
- Shadow: none

**Interaction:**
- Tap sends `ainm.stream.cancel` for the active stream via AINMClient
- Button transitions to disabled state immediately on tap (prevent double-tap)
- Label changes to "Stopping..." while awaiting `stream.end`
- Button disappears when `stream.end` received
- If multiple parallel streams exist, cancels all active streams in the current thread

### Component 4: TypingIndicatorView (STR-02)

**Layout:** Appears inline in the message thread below the last message, before the streaming message (if any). One indicator per participant who is actively typing/processing.

**Appearance:**
- Left-aligned, same position as agent messages
- Leading: 24pt avatar (same `AvatarView` component)
- Three bouncing dots: 6pt diameter circles, `Color(.tertiaryLabel)`, 4pt horizontal spacing between dots
- Label: "{name} is typing..." in `.caption`, `Color.secondary`, to the right of the dots
- For agents: "{name} is processing..." instead of "is typing..."
- Container: no background (transparent), 8pt vertical padding

**Animation:**
- Dots bounce sequentially with 0.15 second stagger
- Each dot animates Y offset from 0 to -4pt and back
- Duration: 0.4 seconds per dot, repeating forever
- Gate behind `accessibilityReduceMotion`: show static dots (no bounce) when enabled

**Lifecycle:**
- Appears when `ainm.presence.notify` received with `status: "processing"` or custom typing status
- Disappears when the participant sends a message or presence changes to non-typing state
- Auto-dismiss after 30 seconds with no update (stale presence guard)

### Component 5: ButtonBlockView (INT-01)

**Layout:** Renders inline within the content block stack, full available width.

**Appearance by style:**

| Style | Background | Text Color | Border |
|-------|-----------|------------|--------|
| `"primary"` | `Color.accentColor` | `Color.white` | none |
| `"secondary"` | `Color(.secondarySystemFill)` | `Color(.label)` | none |
| `"danger"` | `Color.red` | `Color.white` | none |
| disabled (any style) | `Color(.tertiarySystemFill)` | `Color(.tertiaryLabel)` | none |

**Dimensions:**
- Height: 44pt (matches touch target minimum)
- Corner radius: 10pt (iOS standard button radius)
- Horizontal padding: 16pt
- Label centered, `.body` weight bold
- Full available width

**Interaction:**
- Tap (if `confirmation` is null): immediately send ActionBlock
- Tap (if `confirmation` is non-null): show `.confirmationDialog` with confirmation text. Two options: "{label}" (proceed) and "Go Back"
- After ActionBlock sent: button transitions to disabled state with label unchanged
- Loading state while sending: replace label with `ProgressView()` spinner (14pt)

### Component 6: FormBlockView (INT-02)

**Layout:** Renders as a card inside the content block stack. Full available width.

**Container:**
- Background: `Color(.secondarySystemBackground)`
- Corner radius: 12pt
- Padding: 16pt all sides
- Border: none

**Title (optional):**
- `.headline` bold, primary color
- Bottom spacing: 12pt below title

**Field rendering (vertical stack, 16pt spacing between fields):**

| Field Type | SwiftUI Control | Notes |
|-----------|----------------|-------|
| `text` | `TextField` | Single line, `.textFieldStyle(.roundedBorder)` |
| `textarea` | `TextEditor` | Minimum height 80pt, max 200pt, 1pt border `Color(.separator)`, 8pt corner radius |
| `number` | `TextField` with `.keyboardType(.decimalPad)` | Single line |
| `select` | `Picker` with `.pickerStyle(.menu)` | Native dropdown menu |
| `multiselect` | Vertical stack of `Toggle` rows | One toggle per option, `.toggleStyle(.switch)` |
| `checkbox` | `Toggle` | `.toggleStyle(.switch)`, label from `label` field |
| `date` | `DatePicker` | `.datePickerStyle(.compact)`, date only |
| `datetime` | `DatePicker` | `.datePickerStyle(.compact)`, date and time |

**Field labels:**
- `.subheadline` weight regular, primary color
- Displayed above each field input
- Required fields: append red asterisk " *" after label text

**Validation errors:**
- Displayed below the failing field input
- `.caption` size, `Color.red`
- Text: "Required" for empty required fields, "Invalid format" for regex failures
- Validation runs on submit attempt only (not on every keystroke)

**Submit button:**
- Full width, 44pt height, accent background, white text
- Label: value of `submit_label` from the block payload. Agents SHOULD always provide a `submit_label`; if omitted, fall back to "Send Response" as a last-resort default. `.body` bold
- Positioned below all fields with 16pt top spacing
- Disabled (tertiary fill) when form has validation errors after first submit attempt

**Placeholder text:**
- `Color(.placeholderText)` (SwiftUI default placeholder styling)

### Component 7: TableBlockView (INT-03)

**Layout:** Renders as a card inside the content block stack. Full available width.

**Container:**
- Background: `Color(.secondarySystemBackground)`
- Corner radius: 12pt
- Clipped to bounds (overflow hidden)
- No outer padding (table fills container edge-to-edge)

**Title (optional):**
- `.headline` bold, primary color
- 16pt padding horizontal, 12pt padding top

**Table structure:**
- Wrapped in `ScrollView(.horizontal, showsIndicators: true)` for wide tables
- Minimum column width: 80pt
- Column widths: flexible, auto-sized to content with 80pt minimum
- Header row: `Color(.tertiarySystemBackground)` background, `.caption` bold uppercase, 8pt vertical padding, 12pt horizontal padding
- Data cells: `.subheadline` regular, 8pt vertical padding, 12pt horizontal padding
- Row separator: 0.5pt `Color(.separator)` between rows
- Alternating row backgrounds: odd rows `Color(.systemBackground)`, even rows `Color(.secondarySystemBackground)`
- Text alignment per column `align` field (`.leading`, `.trailing`, `.center`)

**Sortable columns:**
- Tappable header text with SF Symbol `chevron.up` or `chevron.down` (8pt, secondary color) trailing the label
- Default: no sort indicator shown
- First tap: ascending (show `chevron.up`)
- Second tap: descending (show `chevron.down`)
- Third tap: clear sort (return to original order)

**Row actions:**
- Rendered as trailing column with header label "Actions"
- Each row shows action buttons as horizontal stack with 8pt spacing
- Button style: compact capsule, 28pt height, 8pt horizontal padding
- Styled using same semantic style mapping as ButtonBlock (primary/secondary/danger)
- Label: `.caption` bold
- Tap sends ActionBlock with full row data as `data` payload

**Empty table (zero rows):**
- Show "No rows to display" text centered in table body area, `.subheadline`, `Color.secondary`

### Component 8: ApprovalBlockView (INT-04)

**Layout:** Renders as a card inside the content block stack. Full available width.

**Container:**
- Corner radius: 12pt
- Padding: 16pt all sides
- Background color varies by status (see color table above)
- Border: 1pt, color matches status tint at 0.3 opacity

**Header:**
- Leading: status icon (SF Symbol, 20pt)
  - `pending`: `clock.fill`, `Color(.systemYellow)`
  - `approved`: `checkmark.circle.fill`, `Color(.systemGreen)`
  - `rejected`: `xmark.circle.fill`, `Color(.systemRed)`
  - `changes_requested`: `arrow.triangle.2.circlepath`, `Color(.systemOrange)`
- Title: `.headline` bold, primary color, next to icon with 8pt spacing
- Status badge: `.caption` bold, status-colored text, trailing aligned
  - `pending`: "Awaiting Approval"
  - `approved`: "Approved"
  - `rejected`: "Rejected"
  - `changes_requested`: "Changes Requested"

**Description (optional):**
- `.body` regular, primary color
- 8pt below title row
- Full width, multi-line

**Option buttons (pending state only):**
- Horizontal stack with 8pt spacing, 12pt top margin
- Each button: 44pt height, flexible width (equal distribution), 10pt corner radius
- Styled using semantic style mapping (primary/secondary/danger)
- Label: `.body` bold, centered

**Resolved state (terminal states):**
- Option buttons hidden
- Show "Resolved" row: SF Symbol `checkmark` + "{selected option label}" in `.subheadline` bold, status-colored
- Previously available options shown as `.caption` `Color(.tertiaryLabel)` text below

**Interaction:**
- Tap option button: immediately send ActionBlock with `data: { "value": "{option.value}" }`
- After sending: all buttons transition to disabled state
- On receiving corresponding ActionBlock or server state update: transition to resolved state
- Error `-32071` (already resolved): show alert "This approval has already been resolved by another participant", dismiss with "Got It", then transition to the server-provided `current_status`

### Component 9: ActionBlockView (read-only display)

**Layout:** Renders inline within content block stack. Displayed when a message of type `.action` is viewed.

**Appearance:**
- Compact row with leading icon
- Leading: SF Symbol `arrow.turn.down.right` at 14pt, `Color.secondary`
- Text: fallback text (e.g., "clicked 'Deploy to Production'"), `.subheadline` italic, `Color.secondary`
- No background, no border
- 4pt vertical padding

### Component 10: FallbackBlockView (INT-05)

**Layout:** Renders inline within content block stack for any unrecognized block type.

**Appearance:**
- Same as existing `.unknown(fallback:)` case from Phase 11
- Render `fallback` field as plain text
- `.body` regular, `Color.secondary`
- No special formatting

Already implemented in ContentBlockRenderer. Extends automatically to new block types via the existing `case .unknown(let fallback)` handler.

## Interaction Contracts

### Streaming Interactions

| Interaction | Behavior |
|-------------|----------|
| Stream starts | StreamingMessageView appears at bottom of thread with blinking cursor. Auto-scroll to bottom (only if user is already at bottom). |
| Delta arrives | Text accumulates in the appropriate block. UI updates at 30-60fps (coalesced, NOT per-delta). |
| User taps "Stop Generating" | `ainm.stream.cancel` sent. Button shows "Stopping..." Deltas may still arrive briefly. Stream ends with `status: "cancelled"`. Partial content preserved. |
| Stream ends (completed) | Cursor disappears. Content stays visible in "finalizing" state. Collapsed signed message arrives via GRDB observation, replacing placeholder. |
| Stream ends (cancelled) | Same as completed. Partial content is the collapsed message content. |
| Collapsed message timeout (5s) | "Not verified" badge appears below message. Content remains readable. |
| User scrolls up during stream | Auto-scroll stops. "New messages" pill from Phase 11 appears at bottom. User can tap to jump to current streaming position. |

### Interactive Block Interactions

| Interaction | Behavior |
|-------------|----------|
| Tap ButtonBlock (no confirmation) | Immediately construct and send ActionBlock. Button transitions to disabled + spinner. |
| Tap ButtonBlock (with confirmation) | Show `.confirmationDialog` with confirmation text. On confirm: send ActionBlock. On "Go Back": no action. |
| Tap disabled ButtonBlock | No response. Visual state clearly communicates non-interactivity. |
| Submit FormBlock | Validate all fields. If errors: show inline error messages below failing fields, do not submit. If valid: send ActionBlock with form data. Submit button transitions to disabled + spinner. |
| Tap sortable table column header | Toggle sort: unsorted -> ascending -> descending -> unsorted. Sort applied client-side only. |
| Tap table row action | Send ActionBlock with full row data. Row action button transitions to disabled + spinner. |
| Tap ApprovalBlock option (pending) | Send ActionBlock with `data: { "value": "{option}" }`. All option buttons transition to disabled. |
| Tap ApprovalBlock option (resolved) | No response. Options not rendered as buttons in terminal states. |

### Typing Indicator Interactions

| Interaction | Behavior |
|-------------|----------|
| Presence "processing" received | TypingIndicatorView appears for that participant in the thread |
| Participant sends message | TypingIndicatorView for that participant removed |
| Presence changes to non-typing | TypingIndicatorView removed |
| 30 seconds without update | TypingIndicatorView auto-dismissed (stale presence guard) |

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Dynamic Type | All text uses SwiftUI semantic styles -- scales automatically |
| Touch targets | 44pt minimum height on all tappable elements (buttons, form fields, table row actions, approval options) |
| VoiceOver: streaming | StreamingMessageView gets `.accessibilityLabel("Agent is generating a response")`. Content updates posted via `.accessibilityValue` on coalesced intervals (not every delta). |
| VoiceOver: stop button | `.accessibilityLabel("Stop generating response")` |
| VoiceOver: typing indicator | `.accessibilityLabel("{name} is typing")` or `.accessibilityLabel("{name} is processing")` |
| VoiceOver: ButtonBlock | `.accessibilityLabel("{label}")`, `.accessibilityHint("Double tap to {label}")`. Disabled state: `.accessibilityTrait(.notEnabled)`. |
| VoiceOver: FormBlock | Each field gets `.accessibilityLabel("{label}")`. Required fields: append "required" to label. Validation errors announced via `.accessibilityValue("{error}")`. |
| VoiceOver: TableBlock | Table announced as "Table with {N} rows and {M} columns". Each cell: "{column label}: {value}". Row actions announced per row. |
| VoiceOver: ApprovalBlock | Status announced: "Approval: {title}, status: {status}". Options announced as buttons. Resolved state: "Resolved as {status}". |
| VoiceOver: Not verified badge | `.accessibilityLabel("Message not verified")`, `.accessibilityHint("The signed message was not received from the server within the expected time.")` |
| Reduced motion | Cursor: static (no blink). Typing dots: static (no bounce). All functional animations (button press feedback) preserved. |
| Color contrast | All semantic colors meet WCAG AA in both light and dark mode. Status colors (yellow/green/red/orange) used only as supplementary indicators alongside text labels and icons. |
